# Penrith Cup Series

Results and series ranking points for the Penrith Cup canoe slalom series, published as a static web page on GitHub Pages and embedded in Google Sites.

## Repository layout

```
index.html                  The results page (plain HTML/CSS/JS, no build step)
do_ranking.py               Calculates ranking points and writes points.json
2026_2027/
  series.json               The races in the season, with dates and results files
  penrith_cup_race1.json    Raw results for one race
  points.json               Generated by do_ranking.py; do not edit by hand
  *.pdf, *.jpeg             Original result sheets and the season flyer
```

## Data format

### `series.json`

Lists every race in the season. A race with `"results": null` has not been run yet and is shown as pending on the page.

```json
{"id": "PC2", "name": "Penrith Cup 2", "date": "2026-10-17", "results": null}
```

### Race results (`penrith_cup_raceN.json`)

Only raw data is stored. Run totals, best times, ranks, time behind and points are all calculated from it.

```json
{
  "race": "Penrith Cup 1 - Flat Water",
  "date": "2026-09-26",
  "venue": "Penrith NSW",
  "classes": {
    "K1M": [
      {"bib": 3, "name": "Chris Tubb", "club": "WSWC",
       "runs": [{"time": 79.89, "penalty": 0}, {"time": 79.48, "penalty": 4}]}
    ]
  }
}
```

Each paddler has two runs. A run without a `status` is complete. Other runs set `status`:

| Status | Meaning | Fields |
|---|---|---|
| (none) | Complete | `time`, `penalty` |
| `"DNF"` | Did not finish | `penalty` if the result sheet shows one |
| `"DNS"` | Did not start | none |

Classes are `C1M`, `C1W`, `K1M` and `K1W`.

## Ranking and points rules

These rules are implemented in `do_ranking.py`. They follow the Australian Canoe Slalom Hub Series ranking, except that ties share a rank and its points.

### Race ranking (per class)

1. A run's total is `time + penalty`.
2. A paddler's result is their best total from their completed runs. DNF and DNS runs have no total.
3. Paddlers are ranked by best total, lowest first.
4. **Equal best totals** (to 0.01 s) share the rank. The next rank is skipped: 1, =2, =2, 4.
5. **Both runs DNF/DNS:** the paddler is not ranked, gets 0 points, and is not counted in N below. They are still listed at the bottom of the race table.
6. **One run DNF/DNS:** the paddler is ranked on their other run.

### Race points

```
N      = max(5, number of ranked paddlers in the class)
points = round_half_up(1000 − (rank − 1) × 1000 / N)
```

- The winner gets 1000 points.
- With the minimum field of 5, a class with 3 finishers scores 1000, 800 and 600 rather than 1000, 667 and 333.
- Paddlers who share a rank get the same points.

### Series standings (per class)

- A paddler's series total is the sum of their race points in that class. Every race counts, with no drop score.
- A race the paddler didn't enter scores 0.
- Equal totals share the rank. Paddlers are listed alphabetically within a tie.

### Combined standings

- **Men:** `round_half_up((C1M total + K1M total) / 2)`
- **Women:** `round_half_up((C1W total + K1W total) / 2)`
- A class the paddler didn't race counts as 0.
- Equal totals share the rank.

### Matching paddlers across races and classes

Paddlers are matched by name, ignoring upper/lower case and extra spaces, so a name must be spelled the same way in every race. `do_ranking.py` warns about pairs of names that are close enough to be spelling variants. The check uses edit distance < 4, with a substitution counting as 2. For example:

```
WARNING: possible duplicate names: 'Jonathon Dore' / 'Jonathan Dore'
```

If the two names are the same person, correct the spelling in the race JSON and re-run.

### Published points are frozen

`points.json` is the published record. When `do_ranking.py` is re-run, it compares the new results against the existing `points.json`. If any points already published for a race would change, it stops and lists them:

```
Published points would change (use --force to overwrite):
  PC1 C1M Timothy Anderson: 800 -> 1000
```

Use `--force` only when a correction to published results is intended.

## Adding a race

1. Convert the result sheets into `2026_2027/penrith_cup_raceN.json`, using the format above.
2. Set that race's `"results"` in `series.json` to the new file name.
3. Calculate points:
   ```
   uv run do_ranking.py 2026_2027/series.json
   ```
   Check the printed standings, and fix any duplicate-name warnings.
4. Check the page locally (see below).
5. Commit and push. GitHub Pages updates the live site.

## Running locally

Requires [uv](https://docs.astral.sh/uv/). The project uses only the Python standard library.

```
uv sync                                  # first time only; creates .venv
uv run do_ranking.py 2026_2027/series.json
uv run python -m http.server 8000
```

Open <http://localhost:8000>. The page has to be served over HTTP to load its JSON files, so opening `index.html` directly from disk will not work.

Useful page URLs for testing:

- `?view=PC1&cls=K1W`: a race, on a specific class
- `?q=casserley`: search across every class
- `?view=about`: the "How it works" tab

## Publishing

The site is served by GitHub Pages from the root of the `main` branch. To embed it in Google Sites, use **Insert → Embed → By URL** with the GitHub Pages address. The Google Sites page then updates whenever the repo is pushed.
